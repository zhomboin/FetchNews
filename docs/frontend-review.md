# 前端页面设计与完成度评估

本文档旨在对 `web/` 目录下的前端页面进行详细的评估，分析其布局、设计、完成度，并识别待实现或可优化的方向。

---

### 1. 登录页 (`features/auth/login-page.tsx`)

-   **文件**: `features/auth/login-page.tsx`
-   **布局与设计**:
    -   典型的居中卡片式登录表单，布局简洁、聚焦。
    -   设计遵循项目极简基调，符合“内部控制台”的定位。
-   **完成度**: **较高**。
    -   已实现完整的用户输入、状态管理（加载中、错误）和提交逻辑。
    -   采用 `Zustand` 和 `TanStack Query` 进行状态管理和数据请求，实践现代、健壮。
-   **待优化**:
    -   **视觉细节**: 可进一步应用“暖白金属”质感，为输入框、按钮增加符合规范的边框、阴影和高光。
    -   **用户体验**: 建议在密码输入框增加“显示/隐藏密码”的切换图标。

---

### 2. 总览仪表盘 (`features/preview/preview-dashboard.tsx`)

-   **文件**: `features/preview/preview-dashboard.tsx`
-   **布局与设计**:
    -   完美实践了“控制台式模块编排”，将审核、草稿、日志等核心模块高效组织在一屏内。
    -   是“暖白金属极简”风格的**样板实现**，为其他页面提供了可复用的组件和样式范例。
-   **完成度**: **较低（作为功能页面）**。
    -   这是一个**纯静态的预览页面**，所有数据均为硬编码。
    -   其核心价值在于**视觉和组件的规范定义**，而非实际功能。
-   **核心任务**:
    -   后续真正的“总览仪表盘”（如 `ops-dashboard-page.tsx`）需将这里的静态组件转化为能接收动态数据的真实组件，并添加数据获取逻辑。

---

### 3. 审核队列页 (`features/stories/stories-page.tsx`)

-   **文件**: `features/stories/stories-page.tsx`
-   **布局与设计**:
    -   布局清晰：页面标题、操作按钮、故事列表。
    -   列表行展示了故事的核心信息，符合“编辑决策面板”对信息密度的要求。
-   **完成度**: **中等**。
    -   **已实现**: 列表通过 `useQuery` 从 API 获取并展示真实数据；实现了“重新生成 Story”的 `useMutation` 逻辑。
    -   **未实现**: 缺乏核心的**审核操作**。用户目前只能“看”，不能对故事执行“批准”、“拒绝”等操作。
-   **核心待办**:
    -   **增加核心交互**: 必须为每个列表项增加审核操作的 UI（如按钮组）和对应的 `useMutation` 逻辑。
    -   **增加筛选与排序**: 应支持按状态、分数、时间等进行筛选和排序。
    -   **支持批量操作**: 考虑增加复选框和“批量批准”等功能。

---

### 4. 草稿与文章页 (`features/articles/*.tsx`)

-   **文件**:
    -   `articles-page.tsx` (列表页)
    -   `article-composer.tsx` (生成器)
-   **布局与设计**:
    -   `articles-page.tsx` 是标准列表页布局。
    -   `article-composer.tsx` 是一个模态框，聚焦于文章生成任务。
-   **完成度**: **中等**。
    -   **已实现**: 文章列表能获取并展示真实数据；文章生成器可选择 `stories` 并请求生成文章。
    -   **未实现**: **没有真正的文章“编辑”功能**。用户可以“生成”，但无法对生成的文章内容进行修改。
-   **核心待办**:
    -   **构建文章编辑器**: 必须实现一个**文章详情/编辑页面**，允许用户对生成的草稿进行内容修改、保存和预览。
    -   **实现版本管理**: 需要为 `article-history-panel.tsx` 等文件构建清晰的 UI，以展示和对比文章的修订历史。

---

### 5. 运维监控页 (`features/ops/*.tsx`)

-   **文件**: `ops-dashboard-page.tsx`
-   **布局与设计**:
    -   直接复用了 `preview-dashboard.tsx` 的组件，并填充了真实的 `ops-summary` 数据，是组件化复用的优秀范例。
-   **完成度**: **较高（作为只读监控）**。
    -   成功调用 API 并将返回的真实数据（平台健康状况、来源告警）填充到监控组件中。
-   **核心待办**:
    -   **增加下钻分析**: 当前页面是“只读”的。应为各个监控模块增加点击下钻（Drill Down）到详情页的能力，以便用户追溯问题根源。

---

### 总结

-   **设计一致性**: **非常高**。所有页面都严格遵循了前端风格规范。
-   **页面完成度**:
    -   **高**: `login-page`, `ops-dashboard-page` (作为监控面板)。
    -   **中**: `stories-page`, `articles-page` (数据展示已实现，但缺失核心操作)。
    -   **低/原型**: `preview-dashboard` (纯视觉原型) 及文章编辑相关页面。
-   **后续开发重点**:
    1.  **实现审核交互**：在审核队列页增加批准、拒绝等功能。
    2.  **构建文章编辑器**：创建文章详情页，实现对内容的修改。
    3.  **增加下钻功能**：让运维面板可点击，以查看详情。
    4.  **丰富列表操作**：为各列表页增加筛选、排序和批量处理能力。
