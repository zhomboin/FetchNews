# FetchNews 实施路线图

## 目标

将系统从“内部闭环可运行”推进到“真实外部能力接入、可观测、可扩展”，同时避免把来源接入、内容智能、协作治理和生产化部署混在同一轮里实现。

## 当前阶段

- Phase 00 - Phase 06：基础能力已具备。
- Phase 07：当前分支的首轮实现已完成 Task 1 到 Task 5。
- Phase 08 - Phase 10：后续阶段。

## Phase 07 当前进度

### 已完成

1. 数据契约和配置基线。
2. `telegram` 真实发布闭环骨架。
3. `wechat / x` 占位真实发布器和 ops 失败归因。
4. `GitHub Releases / Hugging Face / Papers with Code` 真实连接器骨架与增量抓取。
5. API、ops 页面和 ingestion 页面接入 Phase 07 健康字段。

### 下一步

1. 对 `wechat / x` 和真实来源连接器做进一步限流、认证和异常恢复加固。
2. 评估哪些真实外部能力可以从“骨架”升级到真实生产流量。
3. 在此基础上转入 Phase 08 的真实 LLM provider 和 embedding 能力。

## 推荐推进顺序

1. 先完成并加固 Phase 07。
2. 再进入 Phase 08，接真实 LLM provider 和 embedding 能力。
3. 然后完成 Phase 09 的编辑协作治理。
4. 最后收敛到 Phase 10 的生产化部署与运维。

## 路线分层

### 层 1：当前已跑通的内部闭环

- 采集
- 标准化
- 聚类
- 草稿生成
- 审核
- 发布
- 结果回写
- ops 观测

### 层 2：当前已接上的真实外部能力

- 真实发布平台骨架
- 真实来源连接器骨架
- 幂等重试与失败归因
- 平台和来源级 ops 指标
- 前端健康状态展示

### 层 3：后续能力

- 真实 LLM provider
- embedding 去重和召回
- 编辑协作治理
- 生产环境部署和监控

## 约束

- 每个阶段都必须能独立验收。
- 涉及模型字段或表结构变化时，先有迁移，再有实现和文档。
- 真实外部接入优先做小范围闭环，不一次性全量打开。
